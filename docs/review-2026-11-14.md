# Riemann review, 14 November 2026

A full pass over the Python app, the Rust core, the AI sidecar, the injected JavaScript and the build files. A second pass on 14 and 15 November fixed most of what the first one left open and added the features below. Nothing is committed; all of it is in the working tree. Python tests went from 233 to 412 (the AI engine's tests are now among them), and the OCR worker has 8 Rust tests. All pass. The first table lists the first pass. Each of its fixes was checked against the running program as well as the tests, and all but four (13, 17, 19, 20) have automated tests.

Behaviour changes to know about:

- AI search now indexes a PDF when you open the AI search bar or ask the first question, not when the PDF opens. The first start of the engine takes about 30 seconds; the bar says so.
- The single-instance socket is now per user. Your running packaged build uses the old name, so the first new build you start won't hand files to it.
- Your packaged builds (`~/Downloads/Riemann`, the Windows release) still contain the old core and old sidecar. Rebuild them to get these fixes. The AI engine has since moved into the app (`core/ai_server.py`, see the second pass); `assets/riemann_ai_engine/` is no longer used.

New files: `core/ai_engine.py` (shared engine), `core/storage.py` (atomic JSON writes), and tests `test_core_bindings.py`, `test_storage.py`, `test_captions_server.py`, `test_compression.py`. `docs/DevGuide.md` has a new "Semantic Search Engine" section.

## Second pass, 14 and 15 November

You agreed to everything under security, data integrity, reliability and code quality, all ten feature ideas, and a few additions. Build and packaging followed on 15 November (below). Some test items are still open (see "Still open").

### Security and privacy

- Clipboard: sites can write to it; reading asks once per site. `JavascriptCanAccessClipboard` is off.
- Local pages are filtered by the request interceptor: a local page may load only static files from its own folder, and nothing remote apart from navigating to a page. The start page may load its own assets and remote images (its site icons). Turning `LocalContentCanAccessRemoteUrls` off had done the same job but also hid those icons, so it is on again (16 November).
- The LaTeX model pack is pinned by SHA-256 and unpacked with a path check. The download dialog's Cancel works.
- "Manage External Dependencies" installs pinned versions (`core/dependencies.py`).
- The autocomplete sites and the AI subject labels are user settings with generic defaults. `erp.iitkgp.ac.in` and your course names are gone from the code.
- `create_markup_annotation` and the sidecar's `/ws/ai` endpoint are deleted.
- Markdown files open with raw HTML disabled and `javascript:`, `data:` and `file:` links blocked. The start page's edit dialog no longer inserts HTML.

### Data integrity

- Annotation saves still append, but after ten appended updates the file is rewritten in full (signed files excepted). Saved copies are written in full unless the source is signed.
- PDF and JSON annotation sets are merged by annotation ID instead of one replacing the other.
- Riemann's annotation copies live in the app data folder, named by the PDF's `/ID`, so renames and moves keep them. Old copies migrate on first open.
- The library keys papers by `/ID` too.
- Captions and captioned videos get a new name instead of overwriting (`ffmpeg -n`).
- Moves made in Acrobat or Okular are picked up.
- Python now intersects the crop box with the media box, as the Rust core does.

### Reliability and performance

- Renders are held twice, not three times (the `QImage` copy is gone).
- The 34 silent `except Exception: pass` blocks log to `riemann.log` in the cache folder.
- Render workers, thumbnail renderers and the captions server stop at exit even without `aboutToQuit`.
- Tabs no longer stall each other. Each reader renders in a child process with its own PDFium; it falls back to in-process rendering if the child can't start or dies. A test freezes one tab's child and checks that another tab still renders.
- OCR takes a language list from Settings. "Recognise text in pages…" in the Pages menu reads a page range with one Tesseract process per eight pages, shows progress with Cancel, and saves the text as a .txt file.
- A stale single-instance socket is removed and the listen retried.
- `lastFile` was written by every tab and read nowhere; it's gone.
- Test windows kept their mini-player timers running into later tests, which crashed now and then. The fallback `qtbot` in `conftest.py` (pytest-qt isn't installed) now stops them, and the suite runs in under a minute instead of two.
- The scroll benchmark improved on every measure. At 19,000 px/s on the diffusion paper, sharp pages went from 50% to 69%.

### Code quality

- `app.py` is down from 4,200 lines to 625, with the window's behaviour in `window/`. `ui/reader/tab.py` is down from 4,400 to 394, with the rest in `ui/reader/mixins/`.
- Comments inside function bodies moved to the top of each file.
- 67 filler docstrings were deleted, and the 170 that were partly filler (`Args:` and `Returns:` sections restating the signature) were cut down to what the signature doesn't say, or removed.
- `mixins/host.py` declares what the reader mixins share as a `Protocol`, and a test checks a real `ReaderTab` has all of it.
- Every use of the main settings store goes through `core.settings.app_settings()`; the four copies of the dialog-folder helpers are one.
- `hasattr`/`getattr` calls in `ui/reader` went from 308 to 72. State the reader creates later now has a class-level default (usually `None`) on the mixin that owns it, and is tested with `is None`; the shared ones are in the `ReaderHost` Protocol. The 72 left are checks on other objects (the window, sidebar items, workers) and in `widgets.py`.
- Closing a reader called `close()` on the PDF document, which has no such method; the error was swallowed on every close. The call is gone (the document is freed under the PDFium lock when dropped). The Rust doc comments lost their `# Arguments` and `# Returns` blocks the same way the Python docstrings did.
- Every colour in the Python code comes from the palette, which gained `success` and `warning` for the signature banners (dark and light, text contrast checked at 4.5:1 by a test). Document colours (laser, pen, search hits, presentation stage) sit in its `CONTENT` table. A test fails on any new colour literal. `ui/tooltip.py` keeps its own table on purpose; it is the keycap design you approved. The password dialog had its own always-dark stylesheet; it now follows the theme.

### Added

- System tabs: Settings, History, Bookmarks, Downloads and Library open as tabs, once each, with a teal accent.
- Per-site permissions in Settings for camera, microphone, screen sharing, location, notifications, clipboard, pop-ups, autoplay and more, with the defaults you agreed.
- Keycap tooltips everywhere, and the Inter font bundled in `assets/fonts/`.
- The ten feature ideas. Reading: back and forward, citation cards, notes per paper, read aloud with rate and voice settings, presentation mode with a laser pointer. Library: AI search across all papers, BibTeX and CSL-JSON export. Editing: form filling saved into the PDF, page editing. And the command palette.
- Reader toolbar layouts: Default, A to D and Custom, in Settings, Appearance. In full screen, hovering any of the bars keeps them open.

### Build and packaging

- PyMuPDF (AGPL-3.0) is gone from the app and the AI engine. PDF to images, text and HTML use the Rust core; images to PDF uses Pillow; compression uses pikepdf and now keeps transparency (soft masks) that it used to drop.
- The 8 GB AI engine is replaced. It is now part of the app (`core/ai_server.py`, run as a child process): all-MiniLM-L6-v2 in ONNX on onnxruntime, no PyTorch or faiss, with embeddings matching the old ones to 1e-7. The 90 MB model downloads on first use, pinned by commit and SHA-256. The app sends page text instead of the engine opening PDFs, so AI search now works on password-protected files. `riemann-ai/` is removed and the release workflow no longer builds a separate engine; it smoke-tests the engine inside the built exe instead.
- One dependency list: `pyproject.toml`. It lists what the app imports, pinned (the unused jupyter, bleach and similar entries are gone), and its optional groups match the versions the app installs on demand; tests check both. `requirements/xreqs.txt` is generated from it (381 lines down to 162); `requirements.in` and the stale Windows lock are gone.
- PDFium is out of git. `just fetch-pdfium` (`scripts/fetch_pdfium.py`) downloads the exact builds that shipped (Linux chromium/7643, Windows chromium/7749), checked by SHA-256; the release workflow and build scripts call it. The unused Tesseract install step in the release workflow is gone too.
- `cmd.txt` and `logs/test_results.log` are untracked and ignored. Your own files were left where they are.
- `.github/workflows/tests.yml` runs the Python tests, both Rust suites and the lint on every push and pull request.
- Crates are version 6.1.0, on PyO3 0.30, `image` 0.25 and pdfium-render 0.9.5. Pages past 65,535 can be reached (tested with 70,000). Renders, text, links and glyph boxes are identical to the old build, and render speed is unchanged.

## Follow-ups, 16 November

- Tests workflow: the first run failed because the Ubuntu runner lacks `libpulse.so.0`, which QtMultimedia links against. The workflow now installs it with the other libraries Qt needs (`libpulse0`, `libxkbfile1`, `libxshmfence1`, `libgbm1`, `libxcb-dri3-0`, `libxi6`, `libatomic1`).
- Nuitka build time: `--include-package=onnxruntime` and `tokenizers` pulled in their tool subpackages, and through them sympy, mpmath, IPython and jedi (about 900 extra C files; one sympy file took 915 s to compile). They are excluded in `nbuild.sh`, `nbuild.ps1`, the release workflow and `Riemann.spec`; the AI engine imports fine without them.
- The reader's toolbar, side rail, sections sidebar, scroll bars and page-number box follow the page theme (N). The sidebar and scroll bars used to follow the interface theme (Ctrl+D), and the rail's View, Pages and File icons were never re-coloured, so dark icons sat on dark backgrounds. The page-number box has a border in both themes.
- The full-screen button did nothing: it imported `RiemannWindow` from a path that broke when the reader was split into mixins. `tests/test_imports.py` now checks every relative import in the app.
- Toasts: one label per window, reader and browser tab (`ui/toast.py`). A new message replaces the old one at once.
- The memory, network and battery readout in the menu bar widens when its text grows instead of cutting off the end; the battery shows whole percent.
- Presentation mode zooms: Ctrl+Plus, Ctrl+Minus or Ctrl+wheel around the pointer, Ctrl+0 to fit, drag to pan. Turning the page fits it again.
- An empty tab opened in preview mode shows the preview eye, as does the document opened into it.
- Switching to vertical tabs and back sizes the tabs straight away; Qt kept the old sizes until the next tab click.
- The sections and thumbnails button kept its dark icon on a dark toolbar: it was the one toolbar icon never re-coloured. A test now checks every toolbar and rail icon in the dark page theme.
- The floating page controls in full screen sat at 25% opacity for good, because mouse moves over the page never reached them. They now fade out completely when idle, stop catching clicks, and come back on mouse movement (the cursor is polled in full screen), a key or the wheel. Outside full screen (layout D) they stay visible.
- A scroll event arriving after a document closed raised an AttributeError at exit; it is now ignored.
- Each browser profile now owns one request interceptor, shared by its tabs. It used to belong to the newest tab, and Qt holds it only weakly, so closing that tab switched off ad blocking and the local-page rules for every other tab on the profile.

### Hard-coded values (16 November)

- Asset paths: 14 copies of the "where are the bundled files" lookup are now `core/assets.py`. Two of the copies were wrong for PyInstaller bundles (one left out the `riemann` folder, one walked up from `ui/`), so the browser toolbar icons and several window icons would have been missing from a PyInstaller build. The Nuitka build was not affected.
- Settings: the 14 keys used by more than one module, and the defaults two modules must agree on, are named in `core/settings.py`; the three side stores have accessor functions. Stored names are unchanged, so existing settings carry over.
- Endpoints: API, link and model hosts are in `core/endpoints.py`; `127.0.0.1` is written once. The web search engine is a setting (Settings, under Look) used by the address bar, the start page and "Search the web". Address-bar searches are now URL-encoded; before, a query with `&` or `#` was cut short.
- KaTeX, loaded from a CDN in Markdown and reflow views, is pinned by SRI hash as well as version. Checked live: it typesets with the right hashes and is refused with a wrong one.
- The reader's zoom limits, the A4 fallback page size, the debounce timers and the metadata timeouts are named once each.
- The WhatsApp user agents are named side by side. They disagree with each other (the header claims Linux Chrome 144, `navigator.userAgent` Windows Chrome 124) and are left as they were until someone checks which one WhatsApp accepts.
- `scripts/build-excludes.txt` replaces four copies of the build exclusion list. The Windows build script had been missing eight of them.
- Tests run with their own throwaway `HOME` and XDG folders. They had been sharing `/tmp/.config/Riemann` between runs, and would have used a real profile wherever `XDG_CONFIG_HOME` is set.
- Left inline on purpose: layout sizes in pixels, timer intervals used once, and the start page's own scripts (Node isn't installed, so they can't be tested here).

## How Riemann compares

Apps of similar scope: PDF readers (Okular, Sioyek, SumatraPDF, Acrobat Reader, Foxit), reference managers (Zotero), and browsers built for research (Vivaldi, Arc).

What people expect from that group, and where Riemann stands:

| Expected | Riemann |
| --- | --- |
| Tabs, outline, thumbnails, find, zoom modes, facing pages | Yes |
| Annotations saved in the PDF, readable by other apps | Yes |
| Digital signatures: verify and sign | Yes |
| Password-protected PDFs, printing | Yes |
| Back and forward after following a link (Alt+Left) | Yes, since the second pass |
| Presentation mode | Yes, with a laser pointer |
| Read aloud (text to speech) | Yes, with the current sentence highlighted |
| Fill in forms and save them | Yes, saved into the PDF |
| Page editing: delete, reorder, insert, extract | Yes |
| Redaction | Missing |
| EPUB, DjVu, comic book formats | EPUB converts to HTML; DjVu and CBZ are missing |
| Reference manager integration (Zotero, BibTeX library) | BibTeX and CSL-JSON export of the whole library; no Zotero sync |
| Sync of reading position and annotations across devices | Missing |
| Keyboard-driven navigation (vim-style keys, as in Sioyek and Zathura) | Missing |
| Extensions or plugins | Missing |

What Riemann has that none of those do in one app:

- A PDF reader and a full Chromium browser in one window, with split view, so a paper and its arXiv page, code or slides sit side by side.
- Local semantic search across a paper, plus a chat assistant that answers from the document with clickable page citations and works with any of five providers, including a local Ollama.
- Snipping an equation straight to LaTeX.
- Smart dark mode that keeps figure colours readable.
- Live translated captions on any video in the browser, yt-dlp downloads and streaming, an ad skipper, speed control and an audio EQ mode.
- A folder workspace with preview tabs (one click previews, double click keeps), as in VS Code.
- Measured rendering performance that stays sharp at about ten pages a second of scrolling.
